# AI_RULES — Правила разработки для AI-ассистентов

## Главное правило

**Работай итеративно, не забегай вперёд.**

Каждый запрос должен приводить к одному законченному, изолированному изменению.
Не пытайся предугадать будущие требования и не добавляй код «про запас».

## Правила кодирования

1. **Zero Tech Debt.** Пиши чистый код без дублирования. Комментируй неочевидные решения.
2. **Никакого Scope Creep.** Если в задаче сказано сделать кнопку — сделай кнопку.
   Не добавляй побочный функционал.
3. **Один экран = один модуль.** Каждая фича лежит в своей папке и ничего не знает о других.
4. **Никаких монолитных файлов.** Если файл превышает ~150 строк, разделяй его.
5. **Все цвета — только через CSS-переменные Telegram.** Никаких жёстко заданных значений
   (`#fff`, `#000` и т.п.) в стилях компонентов.
6. **Следуй DESIGN_BIBLE.md.** Отступы, скругления, размеры текста — всё должно совпадать.

## Процесс внесения изменений

1. Прочитай `CURRENT_TASK.md` — пойми, на каком мы этапе.
2. Сделай ровно то, что описано в задаче.
3. Обнови `CHANGELOG.md` записью о сделанном.
4. Обнови `CURRENT_TASK.md` — отметь выполненное и предложи следующий шаг.

## Если ты хочешь изменить структуру

Если предложенная архитектура или структура папок кажется неоптимальной:
1. **Остановись.**
2. Объясни, что именно не так.
3. Предложи альтернативу.
4. Жди подтверждения перед внесением изменений.

## Запрещено

* Создавать код для неоговорённых фич (регистрация, профили, загрузка фото,
  логика свайпов, каталог, чаты, лайки, базы данных, Premium, ИИ-подбор).
* Использовать сторонние тяжёлые библиотеки без согласования.
* Менять структуру папок без предупреждения.
* Игнорировать DESIGN_BIBLE.md при вёрстке.
